# رصد: فصل الموقع عن Android (المرحلة التجريبية)

- **الويب**: `bun run build` ما زال يبني TanStack Start مع Supabase؛ لم تُعدّل شاشات المصادقة أو قاعدة الإنتاج.
- **Android**: `bun run android:prepare` يبني واجهة مستقلة `android-local.html` إلى `dist/client/index.html` ويعبئها Capacitor بدون `server.url`. يعمل فتح الخزنة والعمليات الأساسية دون إنترنت.
- الخزنة الحالية مُشفَّرة بكلمة سر قوية (12 حرفاً فما فوق) ومخزنة عبر IndexedDB مع PBKDF2 310k + AES-GCM؛ **ليست PIN بستة أرقام ولا تعتمد حتى الآن على Android Keystore**. لا تُعلن واجهة PIN القصير قبل توفر ربط موثوق بـ Keystore والبصمة.
- الميزات المحلية التجريبية: المحافظ، الدخل والمصروف والديون الفردية والتحصيل والسداد، والذهب والاستثمارات الأساسية (شراء وبيع وتقييم يدوي)، وحفظ نسخ احتياطية مشفرة. **لم تنقل بعد الزكاة الكاملة والعملات المتعددة وباقي وظائف النظام**.
- «حفظ نسخة داخل التطبيق» يحفظ النسخة مشفرة في مساحة ملفات Android الخاصة بالتطبيق؛ ستُحذف هذه النسخة إذا حذف المستخدم التطبيق.
- «مشاركة / حفظ في Google Drive» يفتح لوحة المشاركة الأصلية في Android من نسخة مشفرة مؤقتة ضمن Cache FileProvider. يجب أن يختار المستخدم تطبيق Google Drive إذا كان مثبتاً (أو تطبيق الملفات أو غيره) ويؤكد الحفظ بنفسه. لا يجري تسجيل Google داخل رصد، ولا وصول مباشر لحساب Drive، ولا نسخ تلقائية. اختبار الفتح والإكمال على هاتف Android الحقيقي إلزامي.
- التطبيق المحلي غير متصل بقاعدة Supabase إطلاقاً؛ لا يغيّر بيانات الويب ولا يقرأها. للانتقال في المستقبل يلزم معالج ربط حساب وتحقق من التطابق وحل تعارضات، لا نسخ سجلات عمياء.
- تنبيه أمن: خزنة IndexedDB محمية بكلمة المرور؛ يُطلب مراجعة أثر WebView / IndexedDB وعزل البيانات قبل اعتماد الإصدار النهائي وتوفير حماية Keystore.
- لا تنشر PR #18 إلى main/Google Play قبل فحص التجربة وإكمال كافة الوحدات المهمة للمستخدم؛ هذه تجربة Android جديدة منفصلة وليست استبدالًا جاهزًا للنسخة الكاملة.

## فصل التطبيق التجريبي عن تطبيق رصد القديم
النسخة المحلية التجريبية تحمل الحزمة `app.lovable.rasd.localdev` (اسمها «رصد محلي تجريبي»). يمكن تثبيتها بجانب `app.lovable.rasd` دون الكتابة على بيانات/جلسات التطبيق القديم. لا توجد آلية لنقل بيانات أحدهما للآخر الآن.

## LF-04A: الديون المحلية وترقية الخزنة
- توسّعت صيغة مخزن Android من schema v1 إلى v2 مع مجموعتين `debts` و `debtPayments`، وتُقبل خزائن Android القديمة بعد التحقق من جميع المعرّفات والقيم ثم تُرقى في الذاكرة وتُحفظ بصيغة v2 في أول عملية كتابة تالية.
- تُقبل النسخ الاحتياطية المحلية المشفرة بنمط v1 ويُعاد بناؤها في الذاكرة بعد فك تشفيرها والتحقق منها. **ملفات النسخ لا يتم تعديلها في Drive**.
- الدين المستحق لي عند ربطه بمحفظة = خروج نقدي، والتحصيل = دخول نقدي. والدين المستحق عليّ = دخول نقدي، والسداد = خروج نقدي. **هذه الحركات ليست دخلاً مكتسبًا ولا مصروفًا محاسبيًا**، ولا تُضاف إلى مجموعة `entries`.
- يمكن تسجيل دين تاريخي أو تحصيل دون حركة محفظة باختيار «بدون محفظة»، دون اختلاق حركة نقدية.
- لا يسمح النظام بسداد/تحصيل أكثر من الرصيد المتبقي لكل دين؛ تُحفظ المعاملة مع المحفظة داخل خزنة واحدة مشفرة لضمان الاتساق الذري.
- هذا جزء أولي محدود بالريال السعودي والديون البسيطة؛ ليس بديلاً كاملاً لمحرك `person_ledger` الأصلي أو تصنيفات العملات والزكاة.

## LF-04C: الذهب والأسهم وصناديق الاستثمار (schema v3)
- تُرقّى الخزائن والنسخ المشفرة المحلية schema v1/v2 إلى v3 بعد فحص صلاحيتها، دون تصفير المحافظ أو الديون أو استبدال النسخ الأقدم.
- سجل الأصول `investments` وسجل حركات `investmentTrades` داخل الخزنة المشفرة نفسها. يدعم الذهب بالجرام والأسهم/الصناديق بالوحدة حتى ثلاث منازل عشرية.
- الشراء المرتبط بمحفظة ينقص رصيد النقدية، والبيع يزيده. لا يضيف الشراء مصروفًا ولا يضيف البيع إيرادًا للدخل/المصاريف. الأرباح المحققة تُحسب بعد خصم متوسط تكلفة الكمية المباعة، والربح غير المحقق بناء على سعر سوق يُدخله المستخدم يدويًا.
- لا توجد أسعار فورية، ولا رسوم عمولات أو توزيعات أرباح أو أسهم مجانية أو بيع مكشوف، ولا تتبع تكلفة حسب دفعات FIFO حتى الآن. يتم رفض بيع كمية أعلى من المتاحة.
- حالة «للتجارة» أو «للاقتناء» تُحفظ كتوصيف مقصود **ولا تُعتبر بمفردها فتوى زكوية**. حساب الزكاة يتطلب النصاب والحول ونوع الأصل والالتزامات وبيانات موثقة قبل إطلاق حاسبة نهائية.
- غرض المرحلة: حساب آمن للأرصدة وتفادي تكرار العمليات، وليس نقل جميع خصائص استثمارات الويب دفعة واحدة.

## LF-04D: معاينة زكاة المال محليًا (ليست فتوى)
- `src/native/zakat-preview.ts` و`ZakatPreviewSection.tsx` يوفران حسابًا **قرائيًا فقط** لا ينشئ قيودًا ولا يطلب اتصالًا بسوبا بيز.
- تحديد النصاب ذهب 85 جرامًا أو فضة 595 جرامًا؛ **المستخدم يُدخل السعر المرجعي بنفسه** بدل تعريض المال لسعر افتراضي أو قديم.
- تضاف أرصدة المحافظ المُسجلة بعد حركاتها، ويمكن للمستخدم اختيار **كل أصل استثماري على حدة** لإضافة قيمته السوقية اليدوية؛ لا يدخل ذهب الزينة أو الأسهم أو الأصول الأخرى في الوعاء تلقائيًا بمجرد تسجيلها.
- يمكن للمستخدم إدخال الجزء المؤهل والقابل للتحصيل فقط من الديون المستحقة له، والجزء المؤهل للخصم فقط من التزاماته. يقيد المحرك كلا المدخلين بالقيم القائمة.
- لا يظهر مبلغ زكاة مقدّر قبل تأكيد المستخدم مرور الحول الهجري. عند استيفاء الشرطين يعرض **حساب 2.5% تقريبيًا** فقط. لا يقرر هل استثمارات الشركات والذهب الملبوس والديون ودخل الإيجار زكوية؛ يجب مراجعة الحكم حسب الحالة.
- العملة SAR فقط، وغياب سعر أصل مختار أو وجود رصيد محفظة سالب يمنع عرض رقم قد يكون مضللًا.
- هذه المرحلة لا تتضمن أرشيف حول/سداد زكاة، تحويلات العملة، أحكام الشركات، ولا مقارنة التاريخ الهجري آليًا. **لا تعتمد عليها وحدها لاتخاذ قرار شرعي أو دفع الزكاة.**
