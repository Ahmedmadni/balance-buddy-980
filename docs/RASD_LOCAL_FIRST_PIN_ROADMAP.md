# رصد — اعتماد مقترح Local-first + PIN + مزامنة اختيارية
تاريخ إعداد خطة التنفيذ: 16 أكتوبر 2026. الحالة: **خطة ومسار مستقل للتطوير، وليست ميزة مستخدم جاهزة.**

## المشكلة المؤكدة من الكود وتجربة المستخدم
- `src/routes/auth.tsx` يطلق `lovable.auth.signInWithOAuth("google")` من صفحة تعمل داخل WebView؛ يتم إكمال المتصفح الخارجي لكن جلسة WebView لا تُستعاد.
- `src/routes/_authenticated/route.tsx` يرفض فتح أي شاشة مالية إذا لم توجد جلسة Supabase موثقة.
- معظم الصفحات تستخدم `supabase.from(...)` مباشرة وRLS حسب هوية الحساب، والعمليات المالية تعتمد على جداول/Triggers/RPC. **لا توجد قاعدة بيانات محلية للعملاء الضيوف.**
- `capacitor.config.ts` يحمل الموقع المنشور من `server.url` (SSR). لذلك لا يكفي إضافة IndexedDB أو PIN لكي يعمل التطبيق دون اتصال.
- **ممنوع إضافة زر «استخدام بدون حساب» يفتح الصفحات الحالية فقط**؛ لأن العمليات ستفشل أو تظهر أرصدة 0 مضللة.

## تجربة المستخدم المعتمدة كمواصفات
1. أول تشغيل على هاتف جديد: «استخدم رصد على هذا الجهاز» (افتراضي) أو «لدي حساب وأريد استعادة بياناتي».
2. وضع الجهاز: إنشاء PIN من ستة أرقام كحد أدنى، تأكيده، ثم إنشاء خزنة مالية محلية محمية بمفتاح عشوائي AES-256 محفوظ/مغلّف بواسطة Android Keystore (وليس مفتاحًا مشتقًا من PIN ضعيف وحده). إذا لا تتوفر حماية Keystore مدعومة، **يفشل الوضع المغلق بأمان** أو يطلب اعتماد قفل نظام الجهاز.
3. فتح التطبيق لاحقًا: PIN أو بصمة/قفل نظام إذا اختارها المستخدم. عدد محاولات محدود وتباطؤ/قفل تدريجي وتأكيد عبر آلية موثوقة مدعومة من نظام التشغيل، لا اعتماد على localStorage لتحديد المحاولات فقط.
4. كل وظائف المحافظ والديون والمصاريف والاستثمارات والزكاة تعمل محليًا بعد فك القفل. تعرض الواجهة بوضوح «محفوظ على هذا الجهاز فقط — لم تتم المزامنة».
5. عند اختيار «مزامنة وحماية بياناتي»: فتح تسجيل Google أو طريقة موثوقة أخرى **اختياريًا** في متصفح النظام، ثم عودة جلسة آمنة إلى التطبيق عبر Android App Links/PKCE (مع اختبار فعلي). لا تستخدم OAuth داخل WebView ولا تنقل access tokens عبر رابط عام.
6. ربط الحساب: عرض عدد السجلات والتعارضات ومراجعة نسخة احتياطية مشفرة، ثم رفع أولي تدريجي ومتحقق منه، من دون حذف البيانات المحلية حتى قبول السيرفر لعدد السجلات وتأكيد المستخدم.
7. لو اختفى الجهاز قبل المزامنة/النسخ، البيانات غير قابلة للاستعادة من PIN وحده. يعرض التطبيق هذا التحذير قبل بداية استخدام الضيف ويوصي بنسخة مشفرة بمفتاح/عبارة استعادة مستقلة (12 حرفًا فأكثر)، وليس PIN.

## حدود الأمان
- لا استخدام لـ localStorage لتخزين سجلات مالية أو مفاتيح تشفير أو PIN خام/هاش PIN دون حماية منصة.
- Android: قاعدة SQLite مشفرة على الجهاز، مع مفتاح عشوائي غير قابل للتصدير أو ملفوف بمفتاح Android Keystore يدعم قفل الجهاز. التحقق من سلامة النسخة المحلية والتخزين الذري والمعاملات إلزامي.
- الويب: تسجيل الحساب الحالي مستمر إلى حين توفر خزنة ويب مستقلة بكلمة مرور قوية، ولا يُقبل PIN قصير وحده لحماية نسخة IndexedDB قابلة للنسخ.
- نسخ Backup v2 الحالية تحتوي 19 مجموعة مالية **ولا تشمل المرفقات**. لا تغيّر صيغة v2 ولا تُجرى استعادة مدمرة أثناء المزامنة.
- المزامنة تحتاج `record_uuid` ثابتًا، `revision`، `base_revision`، Tombstones وحل التعارضات؛ لا يجوز `last-write-wins` على أرصدة أو ديون، ولا طمس تغييرات محلية غير متزامنة.
- تحافظ البيانات القديمة لدى مستخدمي السحابة على RLS والمصادقة. ربط جهاز جديد ليس ممرًا لتجاوز Auth أو سياسات Supabase.
- نقل البيانات بدون حساب يكون عبر تصدير مشفر مقصود فقط ولا توجد مزامنة خلفية مجهولة.

## مراحل التنفيذ وأبواب التحقق
**LF-01 — طبقة البيانات:** تعريف واجهة `FinancialRepository` منفصلة عن Supabase، وتغطية العمليات المالية الأساسية باختبارات، بدون تغيير الإنتاج.
**LF-02 — قاعدة البيانات المحلية:** SQLite مشفرة على Android، جداول للـ19 مجموعة + قيود معاملات ومخطط انتقال migrations، واختبارات فقد الطاقة/إغلاق التطبيق.
**LF-03 — دخول محلي:** PIN + Keystore + قفل تلقائي + بصمة اختيارية، اختبار محاولة خاطئة ونسخ ملفات التطبيق وإعادة تشغيله.
**LF-04 — واجهات ماليّة محلية:** استبدال استدعاءات `supabase.from(...)` المباشرة عبر Repository مع تكافؤ الحسابات والمصادر المحسوبة؛ عدم ادعاء دعم لعبة/ميزة قبل تنفيذها.
**LF-05 — حزمة Android مستقلة:** إزالة `server.url` فقط **بعد** أن يتم بناء shell/SPA كاملة مع الواجهة المحلية والمساعدات الضرورية داخل APK؛ اختبار عدم الاتصال بالإنترنت.
**LF-06 — حساب اختياري ومزامنة:** App Links OAuth موثّق، ربط الحساب، مقارنة نسخ ذات Revision/Tombstones، حل تعارض مالي يدوي، نسخ مشفرة ومفتاح استعادة. استكمال اختبارات مستخدمين منفصلين وRLS.
**LF-07 — انتقال مستخدمي السحابة:** إبقاء الحساب القديم وإمكانية استيراد نسخة مع معاينة وعدم الكتابة أو الحذف دون موافقة. اختبار أجهزة جديدة وفقد الهاتف والاستعادة.
**LF-08 — تسليم Android:** اختبار شاشة صغيرة وعربي RTL، PIN/بصمة، قطع الاتصال، المزامنة، النسخ، App Links، AAB، ثم طرح تدريجي.

## إيقاف تلقائي عند الخطر
لا يُدمج مسار Local-first في `main` ولا يُنشر على مشروع الإنتاج قبل نجاح اختبارات الكتابة المحلية ومطابقة الحسابات وRLS والمزامنة. تستمر نسخة السحابة الحالية دون تغيير. يحتفظ المستخدم بخيار النسخ المشفر خلال الرحلة.
